# Data processing inventory

## Purpose and maintenance

This inventory records what customer or operational data the product processes and why. Update it in the same task whenever a data category, purpose, persistence behavior, storage location, retention/deletion behavior, or subprocessor changes. Record actual implementation; target categories below do not assert current production storage.

## Processing principles

- Collect and persist only what actual product behavior requires.
- Do not retain full provider payloads indefinitely by default.
- Webhook capture does not retain raw request bodies/headers, signatures, secrets, tokens, delivery attempt number, or complete provider events. Exact monitored property values are retained because deletion can make a later provider read impossible.
- Signal-processing logs and status do not retain provider values, external object IDs, deduplication keys, or exception messages. Semantic audit values remain customer data because they are the product output.
- Correlation/operation IDs and internal Tenant/connection/signal references are operational metadata, not actor identity. A future durable verified user/operator actor reference must be opaque and is treated as pseudonymous personal data; email/display name is not stored for convenience.
- Technical logging, Product Module semantic audit, and Platform activity audit have separate purposes and lifecycles. Application activity is append-only through the production port, but the database is not WORM or cryptographically tamper-evident.
- Raw evidence and semantic audit history have separate lifecycles: source rows store durable signal UUID provenance without a destructive signal foreign key, so a future evidence-retention job cannot accidentally erase audit history.
- The Deal audit API discloses only connection-scoped product data already retained for the module. Signed user email and user ID are authentication metadata used transiently for validation and are not persisted or logged by this slice.
- Avoid duplicating provider metadata when a Platform Connection reference already establishes provenance.
- Never include OAuth tokens or secrets in this inventory as values, logs, examples, or diagnostic payloads.
- Every customer-owned persisted record must have tenant ownership. Provider-backed records must also retain necessary connection provenance.
- Validate the register against implemented schemas, logs, backups, exports, and external vendors before Private Beta.

Production regions, exact retention periods, customer export/deletion mechanics, and infrastructure vendors remain TBD pending infrastructure and lifecycle decisions.
